# 需求：失败列表展示失败原因，并支持删除失败任务

## 背景

工作台「发送失败」列表只显示英文错误码（如 `SIMILARITY`、`PUBLISH_FAILED`）和重试次数。
使用者（非开发）看不出**为什么失败**、**该怎么处理**；失败条目越积越多，也没有清理入口，只能靠清库重置。

## 用户故事

- 作为运营使用者，我希望一眼看懂每条任务为什么失败，以便决定是重试还是放弃。
- 作为运营使用者，我希望把确定放弃的失败任务从列表里删掉，以便列表只剩还要处理的。

## 验收标准

| ID          | 标准                                                                                                  | 判定方式                |
| ----------- | ----------------------------------------------------------------------------------------------------- | ----------------------- |
| REQ-0001-01 | WHEN 打开失败列表 THEN 每行显示**中文失败原因**（含阶段前缀），下方保留英文错误码小字                 | 界面核对 + 前端测试     |
| REQ-0001-02 | WHEN 失败原因是相似度超标 THEN 显示**实际相似度与闸门值**（如「相似度 0.28 超过 0.45 闸门，已拦截」） | 前端测试                |
| REQ-0001-03 | WHEN 鼠标悬停失败原因 THEN 显示该错误码的处理建议                                                     | 界面核对                |
| REQ-0001-04 | WHEN 点击失败行的「删除」并确认 THEN 调用 `DELETE /api/tasks/:id`，成功后该行消失、汇总计数刷新       | 前端测试 + 后端接口测试 |
| REQ-0001-05 | WHEN 对非 `failed` 任务调用删除 THEN 返回 400 且数据不变                                              | 后端接口测试            |
| REQ-0001-06 | WHEN 删除成功 THEN 改写稿、发布记录、配图记录、任务日志、指纹一并清除，任务详情返回 404               | 后端接口测试            |

## Non-Goals（明确不做）

- 不做批量删除、不做"清空全部失败"。
- 不允许删除已发布 / 发布中的任务：已发布内容必须留证（红线 7 相关），发布中删了会让队列指向空气。
- 不做回收站 / 撤销：删除即不可逆。
- 不改错误码口径本身（`shared/src/errors.ts` 附录 D 仍是唯一真源）。

## 影响面

- 界面：`frontend/src/routes/Detail.tsx`（失败原因列 + 删除按钮）、`frontend/index.html`（新增 `i-trash` 图标）
- 接口：新增 `DELETE /api/tasks/:id`
- 业务：`backend/src/orchestrator/pipeline.ts`（`removeTask`）、`backend/src/infra/db/repo/task.ts`（`deleteTask` 事务）
- 是否触碰红线：涉及**不可逆动作**，已用「二次确认 + 仅 failed 可删 + 事务清库」满足；不涉及发布与采集红线。
