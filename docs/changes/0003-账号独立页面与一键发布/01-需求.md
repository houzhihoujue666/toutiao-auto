# 需求文档 —— 账号独立页面与一键发布

## 背景

CHG-0002 已实现多账号基础设施（独立额度 / 会话 / 队列、跨账号并发闸门）。但账号的「登录 / 切换 / 删除 / 新建」目前散落在设置页里，没有一处能**一眼看全所有账号、并就地发起发布**。用户希望把账号运营集中到一个独立界面。

## 验收标准

| 编号 | 标准 | 可判定 |
| ---- | ---- | ------ |
| REQ-0003-01 | 有独立「账号」页面（独立路由），列出全部账号 | 看路由与导航 |
| REQ-0003-02 | 每个账号行显示：名称、是否当前、登录状态（已登录/已失效/未登录）、额度（今日/剩余）、队列深度、发布中数、待质检数、失败数 | 界面可见 |
| REQ-0003-03 | 每个账号行带一个「条数」输入框，作为该账号一键发布的条数 | 输入框存在且生效 |
| REQ-0003-04 | 每个账号行有「一键发布」按钮，调用该账号的全自动流程（采集→改写→配图→质检→发布） | 点击后该账号开始跑流程 |
| REQ-0003-05 | 账号处于「发布中」——即有待发布队列（queueDepth>0 或 reviewing>0 或 publishing>0）——时，「一键发布」按钮禁用，不可重复点击 | 状态可见且按钮 disabled |
| REQ-0003-06 | 每个账号行有「扫码登录 / 检查登录态 / 退出登录 / 切换 / 删除」操作 | 按钮存在 |
| REQ-0003-07 | 账号操作从设置页整体迁出，设置页回归「可调配置 + 锁定项 + 外部依赖」 | 设置页不再含账号列表与头条登录操作 |

## Non-Goals（明确不做）

- 不做「一键开始全部账号」的批量入口（沿用 CHG-0002 Non-Goal：一次只跑一个账号，不跨账号分摊）。
- 不改并发闸门默认值（仍默认 1，调大由用户在设置页操作）。
- 不为每个账号做独立的自动循环开关 UI（启动已全量拉起，见 CHG-0002）。
- 不改变「同一账号严格串行」这一红线。
