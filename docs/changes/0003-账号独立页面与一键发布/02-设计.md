# 设计文档 —— 账号独立页面与一键发布

## 现状

CHG-0002 后，账号操作分散在前端两处：

- 设置页「账号列表」卡片：新建 / 删除 / 切换；「账号与登录」卡片：当前账号的扫码登录 / 检查 / 退出 / 二维码 / 熔断恢复 / 浏览器目录。
- 顶栏 `AccountPicker`：切换当前账号（保留，不在此次迁移范围）。
- 后端接口齐全：`GET /api/accounts`（返回 `AccountOverview[]`，含 `status/queueDepth/reviewing/failed`）、`POST /api/accounts`、`DELETE /api/accounts/:id/activate`、登录/检查/退出/熔断恢复均支持 `accountId`、`POST /api/run` 支持 `accountId` 与 `count`。

缺的只是「发布中」计数与「一键发布」按钮的界面化。

## 方案

复用 CHG-0002 既有接口与组件，仅做前端重组 + 一个后端字段补充。

### 1. 后端：补 `publishing` 计数

`AccountRuntime.overviewOf` 已调用 `taskRepo.countByStatus(acc.id)`，多暴露一个 `publishing` 字段即可；前端禁用判据据此判断"发布中"。`AccountOverview` 类型加 `publishing: number`。

### 2. 前端：新建 `routes/Accounts.tsx`（独立路由 `/accounts`）

每个账号行渲染：

- 左：`名称` + `当前` 徽标 + 登录态徽标 + `已熔断` 徽标 + 一行小字（今日/剩余/队列/发布中/待质检/失败）
- 右：`条数输入`（每账号独立，默认 `RUN_DEFAULT_COUNT`）→ `一键发布` 按钮 → `扫码登录` / `检查登录态` / `退出登录` / `切换` / `删除`
- `一键发布`：`runOnce(count, acc.id)`；禁用条件 `busy || running[acc.id] || acc.queueDepth>0 || acc.reviewing>0 || acc.publishing>0`
- 二维码弹窗：复用 store 的 `qr`/`clearQr`（WebSocket 推送）
- 熔断恢复 / expired / logged_in 提示：按 `acc.circuit` / `acc.status` 就地展示
- 底部：新建账号输入 + 按钮（沿用设置页逻辑）

### 3. `App.tsx`

- 导航加 `{ to: '/accounts', icon: 'i-account', label: '账号' }`
- 路由加 `/accounts`
- `TITLES` 加 `/accounts`
- 顶栏 `AccountPicker` 的 footer 文案改为「去「账号」页」

### 4. `Settings.tsx`：整体迁出账号操作

删除「账号列表」「账号与登录」两张卡片，把其中的大模型 API 测试 / LLM 登录 / 熔断恢复挪进「外部账号与费用」卡片（它们属于外部依赖，不是头条账号操作）。设置页回归：可调设置 / 提示词模板 / 锁定项 / 外部账号与登录 / 实现红线。

## 红线对照

- 红线 9「不许并行操作同一账号」：`一键发布` 的禁用判据正是为防同一账号重复发起发布，与串行约束一致。
- 红线 5「风控优先于效率」：默认并发闸门仍为 1，本改动不改。

## 判定表

| 场景 | 行为 |
| ---- | ---- |
| 账号 queueDepth/reviewing/publishing 任一 >0 | 「一键发布」禁用，title 提示"发布进行中，无需重复点击" |
| 点击「一键发布」 | 该账号 `runOnce(count)`；成功 toast 显示受理/补采/入队；失败（如额度耗尽）toast 提示原因 |
| 删除有任务的账号 | 后端返回 400，前端提示原因（沿用 CHG-0002） |
| 切换账号 | 仅改当前账号，不影响其他账号的运行 |
