## 一页说明

改造前一个进程只服务一个账号：账号名来自 `process.env.ACCOUNT_NAME || 'toutiao-main'`，
发布队列是进程级单例，任何一次发布都在排同一条队。数据结构其实早就是"每账号一份"
（`account` 表、`task.account_id`、`data/sessions/<账号名>/`），缺的只是多实例管理这一层。

本次把「一个进程 = 一个账号」改成「一个进程 = N 个账号实例 + 一个当前选中项」：

- `AccountRuntime` 按账号 id 惰性构造 `Pipeline` / `CrawlService` / `AccountService`；
- 每个 `Pipeline` 持有自己的发布队列 → 结构上保证同一账号严格串行（红线 9）；
- 新增 `PublishScheduler` 限制"同时在发布的账号数"，默认 1 = 与改造前行为完全一致（ADR-0015）；
- 界面：顶栏账号下拉 + 设置页账号列表（新建 / 切换 / 删除），明细页多账号时显示归属列。

**明确不做**：跨账号统一调度（一次「一键开始」只跑一个账号）、账号改名、多用户与权限、
代理 / IP 隔离、会话目录自动清理、账号级配置。
