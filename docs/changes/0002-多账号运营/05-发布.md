## 回滚方案

- 代码：`git revert <commit>` / 回退到 `v0.1.0`
- 数据：**不需要回滚迁移** —— 本次没有新增 migrations 文件。
  - 当前账号存在 `app_config.activeAccountId`，回退到旧代码会被忽略（旧代码只读 `ACCOUNT_NAME`），不影响运行；
  - 新建的账号行会留在 `account` 表里，旧代码同样忽略，不会报错；
  - `accountConcurrencyLimit` 留在 `app_config` 里被旧版本忽略（多余的行不影响，缺行才会常量兜底）。
- 浏览器会话：跨版本兼容（目录即账号名），不需要清理 `data/sessions/`。

## 实际结果与偏差

与设计文档的偏差，如实记录：

1. **多实例时序引入了一次额外列表请求**：明细页原本在挂载时立刻拉列表，多账号后要知道"当前账号是谁"（依赖 summary），
   会导致 summary 到达后再多拉一次。解决办法是 store 暴露 `summaryLoaded`（success / fail 都置位），明细页等它到位再取列表 ——
   **比设计文档多引入了一个状态位**，因为不想用"禁用 start"之外的副作用路径。已记录在开发过程里，`Detail.tsx` 有注释。
2. **冗余查询键名**：设计稿里写的是 `listTasksByAccount`，实现最终用的是给 `listTasks` / `countByStatus` 加可选 `accountId` 入参 —— 少一个函数、少一处语义分叉，更符合既有代码风格。
3. **原有两个测试做了适配**（语义未弱化，见 `04-验证.md`）：`risk.test.ts` 的队列用例改为实例；`frontend/tests/fixtures.ts` 补齐 `Summary` 新字段。
4. **删除账号比预想更严**：仓库层的 `task` 行对外没有"批量清空"接口，而产品规则是"有留证任务就不许删"，所以**一旦某个账号跑过任务就不能删**（只能换名字重建）。这条限制刻意保留，比开放级联删除更安全。
