# 需求文档 —— 统一启动主界面

## 背景

CHG-0003 将多账号运营独立成「账号」页，但程序启动默认进入的「工作台」只展示**当前激活账号**的流水线，
账号状态（在线/离线、额度、队列）又被拆到「账号」页。用户每次要发布，得先想清楚「我现在在哪个账号的页面」，
状态与发布入口分散在两处，识别成本高。

用户希望：程序一启动就是一个统一的启动主界面，集中展示**每个账号**的当前状态（在线/离线、可用/异常、近期发布情况），
每个账号旁边一个独立的「发布」按钮，点谁就跑谁的发布工作流；其余与核心发布无关的信息和配置全部收进设置页。

## 验收标准（EARS 句式，必须可判定）

| 编号 | 标准 | 判定方式 |
| ---- | ---- | -------- |
| REQ-0004-01 | WHEN 程序启动 THEN 默认进入统一启动主界面（单一路由 `/`，取代原「工作台」与「账号」页） | 看路由与导航；`/` 渲染账号卡片而非工作台 |
| REQ-0004-02 | WHEN 打开启动主界面 THEN 以卡片/列表集中展示**每个账号**的在线/离线（status）、可用/异常（circuit/expired）、近期发布情况（今日已发/剩余、最后发布时间、队列/发布中/待质检/失败数） | 界面核对 / 前端测试 |
| REQ-0004-03 | WHEN 点击某账号卡片的「发布」按钮 THEN 仅触发该账号的全自动发布工作流（`runOnce(count, id)`），不影响其他账号 | 接口测试 / 单测 |
| REQ-0004-04 | WHEN 账号处于「发布中 / 离线 / 异常（熔断或登录失效）/ 当日额度耗尽」之一 THEN 该账号「发布」按钮禁用或替换为「扫码登录」，且保留最小发布间隔闸门 | 界面核对 / 单测 |
| REQ-0004-05 | WHEN 查看启动主界面 THEN 页面只含「账号状态展示 + 发布操作」；原工作台/账号页的流水线轨、风险告警、合规说明、账号管理（新建/删除/切换/检查/退出）不出现在主界面 | 前端测试断言主界面不含这些区块 |
| REQ-0004-06 | WHEN 打开设置页 THEN 提供「账号管理」（新建/删除/切换当前账号/检查登录态/退出登录）与流水线状态、风险告警、合规说明的迁移收口 | 前端测试 |

## Non-Goals（明确不做）

- 不做「一键开始全部账号」的批量入口（沿用 CHG-0002 Non-Goal：一次只跑一个账号）。
- 不改变同一账号严格串行（红线 9）；不新增/修改任何后端接口或 `shared/` 契约字段。
- 不改变发布工作流本身（`runOnce` 入参与返回结构不变）；不改动最小发布间隔、熔断阈值等定案值。
- 不做账号卡片的二级下钻编辑（发布参数如条数沿用每账号输入，复杂配置仍走设置页）。

## 影响面

- 前端：`frontend/src/routes/Launcher.tsx`（新建）、`App.tsx`（导航/路由）、`Settings.tsx`（收口迁移内容）、删除 `Workbench.tsx` 与 `Accounts.tsx`、新增 Launcher 样式。
- 后端 / 契约：**无变更**。复用 `/api/summary` 的 `accounts[]` 与现有账号/登录/熔断接口（`/api/run`、`/api/account/login/*`、`/api/account/circuit/resume`、`/api/accounts`）。
- 红线：仅「红线 9 同账号串行」被沿用（发布中禁用判据），不引入新红线冲突。
