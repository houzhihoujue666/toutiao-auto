# 设计文档 —— 统一启动主界面

> 章节对齐 Google Design Doc：重点是**权衡**，不是实现手册。

## Context and Scope

CHG-0002/0003 已具备多账号底层能力：每个账号独立的额度/会话/队列、`/api/summary` 返回 `accounts[]`、
`runOnce(count, accountId)` 按账号触发全流程、登录/熔断接口均支持 `accountId`。
现状痛点：**启动页（工作台）只讲当前账号**，**账号状态在另一页**，用户要「先看状态 → 切到账号页 → 点发布」，两步且易错。

本次范围：**纯前端重组**，把状态与发布入口统一到启动主界面，把非核心内容收进设置页。无后端/契约改动。

## Goals / Non-Goals

- Goals：启动即见全部账号状态、每账号一个发布入口、主界面零干扰信息、与现有发布契约/红线完全兼容。
- Non-Goals：批量化全部账号发布、改后端、改发布工作流、新增配置项。

## 方案

### 1. 新建 `frontend/src/routes/Launcher.tsx`（路由 `/`，取代 Workbench）

数据来源：store 的 `summary.accounts`（`AccountOverview[]`）。每个账号渲染一张卡片 `launcher-account-<id>`：

- 头部：`名称` + `当前` 徽标（若是 active）+ **状态徽标**（`status-<id>`）：
  - `circuit==='open'` → `异常·已熔断`（红）
  - `status==='expired'` → `异常·登录失效`（红）
  - `status==='logged_out'` → `离线`（琥珀）
  - `logged_in` → `在线`（青）
- 配额行：今日 `usedToday/limit` · 剩余 `remaining` · 信用分 `creditScore`
- 近期发布行：`最后发布 <ago(lastPublishAt)>` · 队列 `queueDepth` · 发布中 `publishing` · 待质检 `reviewing` · 失败 `failed`
- 操作区：
  - `logged_in`：每账号 `条数` 输入（`run-count-<id>`，默认 `RUN_DEFAULT_COUNT`）+ `发布` 按钮（`publish-<id>`）
  - 非 `logged_in`：替换为 `扫码登录` 按钮（`login-<id>`，调 `startLogin`）
  - `circuit==='open'`：附加 `恢复` 按钮（`resume-<id>`，调 `resumeCircuit`）
  - `remaining<=0`：`发布` 按钮显示「今日已发完」并禁用

### 2. 发布逻辑（每账号独立，复刻 CHG-0003 的 `onPublish` + 工作台的间隔闸门）

`publishBusy = queueDepth>0 || reviewing>0 || publishing>0`。点击 `发布`：

1. `publishBusy` 或 `circuit==='open'` → 直接 return（按钮已 disabled，双保险）。
2. 非 `logged_in` → 提示去扫码（按钮已被「扫码登录」替换，正常不可达）。
3. 最小发布间隔闸门：用 `acc.lastPublishAt` + `summary.minPublishIntervalMinutes`，不足则 `notify` 拦截，不调接口。
4. `runOnce(count, acc.id)`；成功 toast 受理/补采/入队；失败（额度耗尽等）toast 原因。
5. `llm.mode==='manual'` 时，发布后拉该账号 `fetched` 任务，若有则弹出 `ManualRewriteDialog`（沿用既有组件，不改动）。

### 3. `App.tsx` 重组

- 导航 `NAV` 改为：`/` 启动（icon `i-overview`）、`/list/reviewing` 明细、`/settings` 设置；**移除「账号」项**。
- 路由 `<Route path="/" element={<Launcher />} />`，移除 `/accounts`；删除 `Workbench`/`Accounts` 引入。
- `TITLES['/']` 改为启动描述；`AccountPicker` 底部文案改指「设置」页管理账号。

### 4. `Settings.tsx`：收口迁移内容

新增/迁移卡片（沿用既有组件 `PipelineRail`/`StatCard`/组件逻辑）：

- **账号管理**：新建账号输入（`new-account-name`/`add-account`）+ 每账号 `切换`/`检查登录态`/`退出登录`/`删除`
  （`settings-account-<id>` 包裹；`switch-/check-/reset-/delete-<id>`），逻辑复用 CHG-0003 的 `Accounts.tsx`。
- **流水线状态**：迁入 `PipelineRail`（各环节存量 + 点数字进明细）+ 六个 `StatCard`（素材池/待发布/发布队列/进行中/今日已发布/失败拦截）。
- **风险与告警**：迁入工作台的告警列表（`alerts`）。
- **合规与风控**：迁入工作台的合规说明（取材网络 / 头条首发 / 间隔 / 熔断不自动恢复）。

既有「可调设置 / 提示词模板 / 锁定项 / 外部账号与登录（LLM）/ 实现红线」保持不动。

### 5. 删除 `Workbench.tsx` 与 `Accounts.tsx`

其内容已被 Launcher 与 Settings 完整吸收，无遗留引用。

## Alternatives Considered

| 方案 | 优点 | 缺点 | 未选原因 |
| ---- | ---- | ---- | -------- |
| A. 维持工作台+账号两页，仅加交叉入口 | 改动小 | 状态/发布仍分散，未解决「启动即见全貌」的根本诉求 | 与本次目标相悖 |
| B. 合并为启动页（本方案） | 启动即全貌、零干扰、每账号独立发布 | 设置页变长 | 符合「主界面只留状态+发布」的明确诉求 |
| C. 启动页=账号卡片，工作台降级为设置里的「流水线详情」 | 与 B 等价，仅命名不同 | — | 采用 B 的命名与落地 |

## 横切关注点

- 风控与限速：每账号最小发布间隔闸门保留（复用 `acc.lastPublishAt`）；全局 `minPublishIntervalMinutes` 不变。
- 幂等与不可逆动作：`runOnce` 自身幂等检查不变；删除账号仍走后端二次校验（有任务则 400）。
- 合规（声明 / 首发）：合规说明从主界面迁到设置页，断言逻辑完全保留，无配置出口（红线写死项不动）。
- 数据脱敏：沿用 store 既有 `pino redact`，本次无新增日志/字段。
- 可观测性：实时日志抽屉、WebSocket 推送、告警提示均不变，仅位置迁移。
