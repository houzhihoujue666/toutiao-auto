# 文档规范（常青层）

> 本项目的文档怎么写、放哪、什么时候冻结、什么时候归档。改这份文件 = 改流程，要显式说明。

版本：v1.0 · 生效：2026-10-23 · Owner：项目Owner

## 一、依据（不是拍脑袋）

| 机制                                                          | 出处                                                                                                           |
| ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 冻结 + 取代（老文档不改，新文档 supersede）                   | MADR 的 `superseded by ADR-0123` 状态                                                                          |
| 一次变更一个目录（spec / plan / tasks）                       | GitHub Spec Kit `specs/001-xxx/`、AWS Kiro `requirements/design/tasks.md`                                      |
| 提案状态机                                                    | Kubernetes KEP：`Provisional → Implementable → Implemented`，外加 `Deferred / Rejected / Withdrawn / Replaced` |
| 设计文档章节（Goals / Non-Goals / Alternatives / 横切关注点） | Google Design Docs                                                                                             |
| 文档四象限（教程 / 指南 / 参考 / 解释）                       | Divio Documentation System                                                                                     |
| 变更六分类 + Unreleased + 倒序                                | Keep a Changelog 1.1.0                                                                                         |
| 提交前缀与版本号联动                                          | Conventional Commits 1.0.0 + SemVer                                                                            |
| 阶段评审、基线冻结、变更单（影响分析 + 审批）                 | GB/T 9385 需求基线化与变更控制实践                                                                             |

## 二、三层模型与判定表

| 判定问题                                             | 归类   | 放哪                                                | 可否改写            |
| ---------------------------------------------------- | ------ | --------------------------------------------------- | ------------------- |
| 描述的是**系统当前事实**（架构、接口、配置、操作）？ | 常青层 | `10-architecture/` `20-reference/` `30-operations/` | ✅ 必须随代码同步   |
| 记录的是**一次决策及理由**？                         | 决策层 | `decisions/NNNN-*.md`                               | ❌ 冻结，只取代     |
| 描述的是**某次功能变更**的意图与方案？               | 变更层 | `changes/NNNN-xxx/`                                 | ❌ 批准即冻结       |
| 已上线 / 被取代 / 被否决 / 长期不做？                | 归档层 | `archive/YYYY-Qn/`                                  | ❌ 只读，不删除     |
| 事故与经验教训？                                     | 沉淀   | `postmortem/`                                       | ✅ 可补充，不改结论 |

**唯一真源原则**：同一事实只在一处定义，其它地方只链接。发现两处都在写同一件事 → 保留常青层那份，另一处改为链接。

## 三、命名

| 对象         | 格式                                                                           | 示例                                                  |
| ------------ | ------------------------------------------------------------------------------ | ----------------------------------------------------- |
| 变更包       | `changes/NNNN-简短标题/`                                                       | `changes/0001-失败列表展示失败原因与删除按钮/`        |
| 变更包内文件 | `01-需求.md` `02-设计.md` `03-任务.md` `04-验证.md` `05-发布.md` + `README.md` | 顺序即阶段                                            |
| ADR          | `decisions/NNNN-短横线标题.md`                                                 | `decisions/0014-文档治理采用三层模型与adr取代机制.md` |
| 需求标识     | `REQ-NNNN-MM`                                                                  | `REQ-0001-01`                                         |
| 归档         | `archive/YYYY-Qn/`                                                             | `archive/2026-Q4/`                                    |

ADR 编号从 **0014** 起（ADR-1 ~ ADR-13 已在 legacy v4.0 §3.3 定案，见 `decisions/README.md`）。

## 四、文档头元信息（每个 md 都要有）

```yaml
---
id: CHG-0001
title: 失败列表展示失败原因与删除按钮
status: done # draft | review | approved | implementing | done | archived | superseded
owner: 项目Owner
created: 2026-10-23
updated: 2026-10-23 # 冻结后不再变
code_version: v0.1.0 # 关联的代码基线（git tag）
superseded_by: # 空 = 有效；被取代时填取代者编号
---
```

**可追溯三问**：谁改的（owner）、什么时候（git 历史 + updated）、为什么（变更包 / ADR 的 Context）。

## 五、状态机

```
draft → review → approved ──(冻结)──→ implementing → done → archived
                     │                                  │
                     └──→ rejected                      └──→ superseded
```

- `approved` = **基线**：此后内容一字不改。
- 需要改 → 新建变更包或新 ADR，在**原文档头部**加一行 `已被 XXXX 取代（日期）`，并从新文档链回原文档（方便后人做文档考古）。
- 已发布（`done`）满一个季度 → 移入 `archive/YYYY-Qn/`，只在 `INDEX.md` 留记录。

## 六、版本与基线

1. **代码**：SemVer `MAJOR.MINOR.PATCH` + git tag（`v0.1.0`），tag 即基线。
2. **提交**：Conventional Commits（`feat(scope): …` / `fix:` / `docs:` / `BREAKING CHANGE:`），变更包编号写进提交正文。
3. **CHANGELOG**：根 `CHANGELOG.md`，六分类（Added / Changed / Deprecated / Removed / Fixed / Security），`Unreleased` 区日常累积，**倒序 + ISO 日期**。CHANGELOG 是写给人看的，**不是 git log 的堆砌**。

## 七、单人项目的裁剪（避免过度官僚）

**必做**：`INDEX.md`、`decisions/`（只写有争议/难逆转的决策）、`changes/NNNN-xxx/`、`CHANGELOG.md`。
**可合并**：小改动把 01~05 合成 `README.md` + 一份设计说明。
**可省**：正式评审会（改成自己过 checklist）、需求跟踪矩阵（改成任务带需求 ID）、文档站点、DMS。
**不可省**：冻结 + 取代、归档区、CHANGELOG。
