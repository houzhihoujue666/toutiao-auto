# 实现现状与已知差异（常青层 · 唯一真源）

> 校对基线：2026-11-05，对照当前工作区源码与测试。
> 用途：当文档（README、历史设计文档、变更包）与代码说法不一致时，在这里登记**事实与处置**，避免同一个坑被反复调查。
> **判定原则：以代码 + 测试为准。文档写的是意图，代码才是事实。**

## 一、这份文档管什么、不管什么

| 管                                                 | 不管                                                      |
| -------------------------------------------------- | --------------------------------------------------------- |
| 记录「文档与代码对不上」的观察、真源位置、处置结果 | 操作步骤（去根 `README.md`）                              |
| 记录改版后的残留代码 / 未消费的后端字段            | 架构设计与接口契约全文（将来进 `20-reference/` 其它文档） |
| 记录冻结文档里的错字、状态不一致（只登记，不改写） | 重写或修订 ADR / 变更包                                   |
| 给出「改代码时要同步哪些文档」的清单               | 替代 `docs/INDEX.md` 的文档地图                           |

发现新的不一致，就在第三节追加一行；**不要**散落在聊天记录、代码注释或多个文档里（文档规范「唯一真源原则」）。

## 四、冻结层怎么处理

- `decisions/`、`changes/`、`archive/` 一律**不原地改写**（`docs/00-guide/文档规范.md` §2、§5）。
- 发现错字或状态不一致 → 在本文第三节登记，例如 D7。
- 确实需要正式更正 → 新建 ADR 或新变更包，在原文档头部加「已被 XXXX 取代（日期）」，并从新文档链回原文。
- 常青层（本文件、`INDEX.md`、红线文档、根 `README.md`）则**必须随代码同步更新**，改代码不改文档视为未完成。

## 五、改动代码时要同步什么

| 你改了……                 | 需要同步……                                                                                                  |
| ------------------------ | ----------------------------------------------------------------------------------------------------------- |
| 前端路由 / 页面结构      | README「多账号」「头条登录」「调试小贴士」+ 本文 §2                                                         |
| npm scripts              | README「常用命令」表                                                                                        |
| 启动方式 / 代理配置      | README「启动」章节 + 本文 §2                                                                                |
| WebSocket 消息结构       | `shared/src/types.ts`、`backend/src/infra/bus.ts`、`frontend/src/state/store.tsx` **三处同改**（D4 的教训） |
| 界面新增/移除功能        | README 相关章节 + 本文 §3 追加一行（若产生残留代码）                                                        |
| 发现任何文档与代码不一致 | 本文 §3 追加一行；冻结层只登记不改写                                                                        |
