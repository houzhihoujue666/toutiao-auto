# toutiao-auto 功能开发流程

本仓库的规矩全部写在文件里，你的职责是**严格照做、不要自由发挥**。仓库文件永远优先于任何聊天记录。

## 开工前必读（按顺序，一个都不能跳）

1. `docs/10-architecture/红线与约束.md` —— 10 条硬红线，违反即为不合格产出。
2. `docs/decisions/README.md` —— 已定案决策（ADR），**不要重复讨论已定案的事**。
3. `docs/00-guide/开发流程.md` —— 阶段门禁与逐阶段 checklist，本技能是它的执行器。
4. `docs/20-reference/实现现状与已知差异.md` —— 文档和代码对不上时该信谁。

## 第一步：判断走哪条流程

判定标准只有一条：**是否存在「选错了会返工」的抉择**。

| 情形 | 流程 |
| --- | --- |
| 改数据结构 / 迁移、发布不可逆动作、≥2 种可选方案、动到红线相关代码、跨前后端契约 | **完整流程**（第二步） |
| ≤ 半天、方案无争议 | **迷你流程**（第三步） |
| 修 typo、调样式、加日志，方案不模糊没有权衡 | 直接改代码 + 测试，CHANGELOG 记一笔，不写文档 |

拿不准时，按完整流程走——多写一份文档比返工便宜。

## 第二步：完整流程

1. **建变更包**：复制 `docs/templates/` 下的模板到 `docs/changes/NNNN-xxx/`（编号取现有最大值 +1，目录名格式 `NNNN-短横线英文标题`）。
2. **`01-需求.md`**：每条需求写成可判定句（`WHEN … THEN …`，EARS 句式），标注唯一 ID（`REQ-NNNN-01`），写明 **Non-Goals**（明确不做什么），说明影响面。这份文档是意图的唯一来源，**不要从聊天记录里回忆需求**。
3. **`02-设计.md`**：Context/Goals、**≥2 个备选方案对比**（说明为什么没选）、横切关注点（风控与限速、幂等与不可逆、合规、数据脱敏）、影响文件清单。
4. **`03-任务.md`**：按用户故事组织、带依赖、可勾选、能映射回需求 ID。
5. **实现**：契约（`shared/`）先行，前后端围绕契约开发；垂直切片，每步都是能真跑的链路，不铺空壳。
6. **验证**：新增/更新测试覆盖每条验收标准；`npm run typecheck` 与 `npm test` 全绿；改动涉及平台选择器或发布流程时加跑 `npm run selftest` 与 `npm run e2e`；证据写进 `04-验证.md`。
7. **沉淀**：常青层文档随代码更新；有争议或难逆转的决策写 ADR（`docs/templates/adr-template.md`）；更新 `docs/INDEX.md` 变更总表；根 `CHANGELOG.md` 按六分类记一笔。

## 第三步：迷你流程

一个变更包 `README.md` 搞定（需求 + 设计 + 任务 + 验证压缩在一起），其余同完整流程的第 5~7 步。

## 硬约束（每一步都适用）

- **文档与代码冲突时，以代码和测试为准**，再按常青层规则把文档同步回来。
- 变更包与 ADR 一旦批准即**冻结**：不原地改写，推翻时写新文档、老的标 `superseded`。
- 发现不在本次改动范围的文档不一致：登记到 `docs/20-reference/实现现状与已知差异.md`，**别顺手改冻结局**。
- 不碰 `data/`（运行期数据）、不提交任何登录态、Key、`.env`。
- 提交信息遵循 Conventional Commits，正文写变更包编号。
- 平台页面会变：选择器集中在 `backend/src/config/selectors/`，禁止散落硬编码。
